# 2026-11-06: Raster layers from cloud-optimised GeoTIFFs

**Release:** 2026-11-06 · **Action needed:** yes

## Summary

Raster layers (rainfall, evapotranspiration, biomass, land cover, elevation, slope,
hillshade) are served as cloud-optimised GeoTIFFs read where FAO, ESA and Copernicus host
them, and drawn and cut by a TiTiler tile server. The tile server is a setting
(`TITILER_URL`), so an IsDB-hosted TiTiler can take over without code changes.

## What users will notice

- The same layers in the Data Catalog and the project Data catalog tab, with more
  WaPOR products.
- Land cover appears from zoom level 7 and terrain from zoom 8; below that, display-only
  services fill in.
- New **View only** layers (NDVI, land surface temperature, population, yearly land
  cover, imagery Wayback) can be shown and printed but not downloaded or analysed.
- NDVI annual means and air temperature are available as view-only layers for now; they
  return as analysis layers once processed into GEIDA's own storage.

## What administrators must do

1. Remove the obsolete settings `EE_KEY` and `EE_KEY_FILE` from `backend/.env`, and
   delete the key file they pointed to.
2. Optionally set the raster services (defaults shown):
   ```ini
   TITILER_URL=https://titiler.waterinag.org
   STAC_API_URL=https://earth-search.aws.element84.com/v1
   ```
3. Allow outbound HTTPS from the server to the TiTiler host and the data hosts
   ([Prerequisites](../setup/index.md#network-access)).
4. Set Apache's `ProxyTimeout` to 180 seconds (already in `deploy/apache/geida.conf`):
   GeoTIFF downloads can take up to two minutes.
5. Run `deploy.sh`; it updates the conda environment.

## Compatibility

- Database migrations: no
- API: `/api/projects/<code>/satellite/<id>/xyz/<z>/<x>/<y>.png` added for project tiles.

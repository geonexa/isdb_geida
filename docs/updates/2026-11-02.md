# 2026-11-02: Repository restructure

**Release:** 2026-11-02 · **Action needed:** yes

## Summary

The repository was reorganised so that the backend and frontend are separate,
self-contained folders, with documentation, deployment files, and personal and
credential folders kept apart. Reference data now load with a single idempotent
`seed` command.

## What users will notice

Nothing: the platform behaves as before.

## What administrators must do

On an existing server, move data that the old layout kept elsewhere:

| Old location | New location | Action |
|---|---|---|
| `static_data/` | `backend/data/` | `mv static_data/* backend/data/`, or set `DATA_DIR` in `.env` |
| `modules/` | `backend/modules/` | None (comes with the code) |
| `backend/data/*.csv`, `*.geojson` | `backend/seeds/data/` | None (comes with the code) |
| `deploy/apache.conf` | `deploy/apache/geida.conf` | Update the live config if it was a symlink |
| `config/settings.py` | `config/settings/` package | None: `DJANGO_SETTINGS_MODULE=config.settings` is unchanged |

The conda environment is now called **`geida`** (was `geida-react`):

```bash
conda env create -f backend/environment.yml
# edit the conda path in /etc/systemd/system/geida-*.service if it named geida-react
sudo systemctl daemon-reload && sudo systemctl restart geida-api geida-worker
conda env remove -n geida-react
```

Then run `python manage.py seed` once (also part of `deploy.sh` from now on).

## Compatibility

- API or URL changes: no

# 2026-11-16: Project reports, Toolbox on the server, Analytics project layers

**Release:** 2026-11-16 · **Action needed:** yes

## Summary

Projects get a **Reports** tab that generates PDF and web reports from their analyses, with share links. The
Toolbox runs on the server with saved results, and the Analytics workspace can load a project's layers.

## What users will notice

- **Reports** tab in the project workspace (see [Features](../introduction/features.md#project-reports)).
- **Toolbox** results are saved and can be deleted; analysis runs can be deleted too.
- **Analytics**: a project picker in the Layers panel lists the project's analysis and Toolbox layers.
- Projects can only be opened after signing in.

## What administrators must do

1. Update the conda environment (new: `weasyprint`, `brotli-python`; pip: `markdown`, `wasmtime`):
   `conda env update -f backend/environment.yml --prune`
2. Run the migrations (`toolbox.0001`, `projects.0003_map_layouts`, `reports.0001`): `python manage.py migrate`
3. Restart the web server and the Celery worker (reports are generated on the analysis queue).
4. Optional `.env`: `GEOLIBRE_WASM`, `TOOLBOX_TIME_LIMIT` (see [Configuration](../setup/configuration.md)).

Report files go to `MEDIA_ROOT/reports/<report>/v<n>/` (a few MB per version); basemap tiles for report maps are
cached in `DATA_DIR/cache/report_tiles/`. The server needs outbound HTTPS to `server.arcgisonline.com` for report
maps (without it, maps are drawn without a basemap).

## Compatibility

- Database migrations: yes (back up first).
- Breaking changes: project pages and the projects API now need a signed-in user (401 otherwise).
